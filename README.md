# Entry Info Bot — Console edition

엔트리 이야기에서 **본인 또는 다른 사람**이 다음 명령어를 *새 게시글 본문*에 작성하면, 현재 로그인한 봇 계정이 **그 게시글에 댓글**로 정보를 자동 작성하는 JavaScript 봇입니다.

```text
!'12옴'정보
```

> 브라우저 개발자도구 콘솔 실행 방식입니다. Chrome 확장 프로그램을 설치할 필요가 없습니다. 비공식 엔트리 GraphQL API를 사용하므로 실제 사이트 업데이트에 따라 동작하지 않을 수 있습니다.

## 실행 방법

1. 댓글을 달 **봇 계정**으로 엔트리에 로그인합니다.
2. 엔트리 이야기 목록 페이지 `https://playentry.org/community/entrystory/list?sort=created&term=all`에 접속합니다.
3. 이 저장소의 **[`console.js`](./console.js)**를 열고 전체 코드(Ctrl+A, Ctrl+C)를 복사합니다.
4. 엔트리 이야기에서 **F12 → Console**을 열어 코드를 붙여넣고 Enter를 누릅니다. 신뢰하는 코드인지 먼저 검토해 주세요.
5. 자동 댓글 실행을 확인하는 대화상자에서 **확인**을 누릅니다.
6. 봇 실행 이후 **본인 또는 다른 사람**이 `!'닉네임'정보` 글을 새로 작성하면, 봇이 해당 글에 댓글을 남깁니다.
7. 이미 올라온 명령어 게시글들에도 답변하려면 `await EntryInfoBot.replyToAllRecentCommands()`를 실행합니다. 최근 최대 100개 글에서 유효한 명령어를 전부 대기열에 넣고 차례로 답합니다. `replyToRecentCommand("삼류")`는 해당 조회 닉네임의 모든 글을, `replyToOwnPost("삼류")`는 그중 본인이 쓴 모든 글을 예약합니다.

코드는 외부 서버에서 추가 스크립트를 내려받아 실행하지 않습니다. 비밀번호를 입력받거나 인증 토큰을 GitHub 또는 저장소에 전송하지 않습니다. 로그인한 엔트리 페이지의 세션만 이용합니다.

## 명령어와 댓글

명령어는 다음처럼 **ASCII 작은따옴표로 닉네임을 감싸야** 합니다.

- `!'12옴'정보` 또는 `!'12옴' 정보` → 둘 다 인식해 해당 닉네임의 작품 수, 팔로워, 팔로잉, 인기작품(인작), 스태프 선정(스선) 수를 조회
- `!'요니작가_온작' 정보` → 공백이 있어도 정상 명령어로 인식 (일반/곡선 작은따옴표 지원)
- `!김곤충 정보`, `!김곤충정보` → **작은따옴표 누락**을 감지해 해당 게시글에 **올바른 명령어 형식 안내 댓글** 작성
- `!"김곤충"정보`, `!'김곤충 정보` → 큰따옴표 사용 또는 닫는 작은따옴표 누락도 형식 오류로 감지
- `!도움말` 등 `정보`로 끝나지 않는 일반 명령어 → 무시
- **글 작성자의 닉네임과 조회하려는 닉네임이 정확히 같으면**, 사용자 검색 API가 실패하더라도 게시글의 작성자 ID로 프로필을 조회함
- `!'없는닉네임'정보` → 닉네임이 실제로 없다는 것을 API로 확인한 경우에만 `그런 유저 없음`
- `!12옴정보` → 무시 (형식이 다름)

댓글 예시:

```text
📊 12옴님의 정보
작품 수: [실제 조회한 수치]개
팔로워 수: [실제 조회한 수치]명
팔로잉 수: [실제 조회한 수치]명
인작 수: [실제 조회한 수치]개
스선 수: [실제 조회한 수치]개
```

## 콘솔 명령어

```js
EntryInfoBot.start()                // 자동 댓글 시작
EntryInfoBot.preview()              // 댓글을 작성하지 않는 미리보기 모드
EntryInfoBot.status()               // 현재 상태 및 대기열 확인
await EntryInfoBot.inspectRecent()  // 최근 최대 100개 글의 명령어 인식 여부 확인 (댓글 없음)
await EntryInfoBot.replyToRecentCommand("요니작가_온작") // 최근 같은 명령어가 있는 모든 글 예약
await EntryInfoBot.replyToAllRecentCommands() // 최근 모든 닉네임 정보 명령어 글 예약
EntryInfoBot.parse("!'요니작가_온작' 정보") // 정상 명령어에서 닉네임만 파싱 (API 요청 없음)
EntryInfoBot.classify("!김곤충 정보") // 형식 오류 여부 확인 (API 요청 없음)
EntryInfoBot.loadDatabase()         // 로컬 data.json을 선택하는 버튼 표시 (1회 불러오기)
EntryInfoBot.stop()                 // 즉시 자동 댓글 중지
await EntryInfoBot.replyToOwnPost("삼류")  // 내가 올린 해당 명령어 글 모두 예약 (최근 100개)
await EntryInfoBot.test("12옴")    // 실제 API로 유저 정보 조회 테스트, 댓글 작성 없음
EntryInfoBot.help()                 // 사용 가능한 명령어 안내
```

브라우저에서 코드를 다시 붙여넣으면 기존 타이머를 종료하고 다시 실행할 수 있습니다.

## 동작과 안전장치

- 자동 감시는 **봇 실행 이후 작성된 모든 명령어 글**을 수집합니다.
- 이미 올라온 글도 `replyToRecentCommand("조회대상닉네임")`으로 최근 최대 100개 글 중 해당 명령어가 작성된 **모든 게시글**을 예약합니다. `replyToAllRecentCommands()`는 조회 대상과 관계없이 모든 유효 명령어 글을 예약합니다.
- 감시 도중 마지막 확인 글이 최신 20개에서 밀려나도 최대 100개까지 추가 조회해 누락을 줄입니다. 100개가 넘는 급격한 신규 글, API 실패, 브라우저 종료 등의 상황에서는 일부가 누락될 수 있습니다.
- 매 약 15초마다 최근 엔트리 이야기 목록을 조회합니다. 브라우저의 백그라운드 탭은 요청이 지연될 수 있습니다.
- 글 작성자가 봇 계정이어도 명령어가 정확하면 응답합니다. 단, 댓글을 감지 대상으로 사용하지 않으므로 자기 댓글에 연쇄 응답하지 않습니다.
- 실행 이전에 올린 글은 자동 감시에서는 건너뛰며, `replyToOwnPost("삼류")` 명령어로 내 명령어 글 **모두**를 대기열에 넣을 수 있습니다.
- 새 게시글 ID를 댓글의 `target`으로 사용하고, `targetSubject: "discuss"`로 댓글을 작성합니다. 새로운 게시글을 따로 올리는 방식이 아닙니다.
- **각 글마다 댓글을 하나씩** 별도로 작성합니다. 정상 명령어에는 유저 정보를, 잘못된 작은따옴표 형식에는 예시 명령어를 안내합니다.
- 형식 오류 안내 역시 30초당 최대 1회, 1시간당 최대 20회 댓글 시도 제한을 적용합니다. 별도의 반복 안내로 서버 제한을 우회하지 않습니다. 많은 요청은 수 시간에 걸쳐 처리될 수 있습니다.
- 대기열은 최대 200건이고, 초과분은 콘솔에 알립니다. 대기열은 브라우저 `localStorage`에 저장하므로 새로고침 후 코드를 다시 실행해도 이어서 처리할 수 있습니다.
- 댓글 발행 성공 여부가 불확실한 경우 중복 댓글을 피하기 위해 자동 재시도하지 않습니다.
- 처리한 글 ID와 댓글 시도 시각만 같은 브라우저의 `localStorage`에 저장해 중복 응답을 방지합니다.
- HTTP 401/403/429 또는 CAPTCHA/도배 방지 응답을 받으면 중지하고 제한을 우회하지 않습니다.
- 닉네임을 정확히 비교하며, 조회 오류를 `그런 유저 없음`으로 오판하지 않습니다.
- 형식이 잘못되었더라도 **짧은 단독 명령어**이고 `!`로 시작하고 `정보`로 끝나는 경우에만 오류 안내를 시도합니다. 일반 대화 글이나 다른 명령어에는 반응하지 않습니다.
- 작은따옴표 양쪽을 생략한 `!김곤충 정보` 같은 요청은 사용자 조회 API를 호출하지 않고 바로 `⚠️ 명령어 형식 오류\n닉네임 양쪽에 작은따옴표(')를 넣어 주세요.\n권장 형식(공백 없이): !'김곤충'정보`라고 안내합니다. 기존에 유효했던 `!'김곤충' 정보`도 계속 허용합니다.
- 조회 대상이 글 작성자와 동일한 닉네임이면 게시글에 포함된 작성자 ID를 먼저 활용해 닉네임 검색 API를 거치지 않습니다. 사용자 프로필의 닉네임과 ID가 일치하는지 추가 검증합니다.
- 닉네임 검색은 우선 엔트리 GraphQL을 조회합니다. API가 HTTP 400 등으로 실패하면 **비공개 `ent2-backup/data.json`을 PC에서 직접 불러와 사용할 수 있습니다.**
- `ent2-backup`은 비공개 저장소이므로 비로그인 `raw.githubusercontent.com` URL에서 404를 받는 것이 정상입니다. **이 저장소를 공개하거나 개인 데이터 파일을 다른 공개 저장소로 업로드하지 마세요.**
- 로컬 DB는 브라우저 탭의 메모리에만 보관합니다. 파일 내용을 외부 서버에 전송하거나 브라우저 저장소에 저장하지 않습니다. 탭을 새로 열면 다시 선택해야 합니다.
- 엔트리 기본 닉네임 검색이 실패하면 엔트리 스페이스 사용자 검색 API도 확인합니다. 브라우저의 교차 출처 정책 때문에 보조 API가 실패할 수도 있습니다.
- 실시간 검색 결과가 **0명으로 확인된 경우에만** `그런 유저 없음`을 댓글로 남깁니다. 과거에 저장한 DB에 없다는 이유만으로 없는 유저라고 단정하지 않습니다.
- 모든 검색 API가 실패하면 최대 3회까지만 조회한 후 `⚠️ 현재 유저 정보를 확인할 수 없습니다.`라는 안내 댓글을 한 번 남깁니다. 실패한 요청을 대기열 뒤로 보내 다른 사람의 요청도 처리합니다.
- 서버에서 요청 제한을 반환하면 자동으로 멈추며 제한을 우회하지 않습니다.
- 같은 닉네임의 유저 정보 결과는 약 2분간(없음 판정은 30초) 메모리에 캐시합니다. HTTP 400 오류가 난 검색 경로는 세션 동안 재사용하지 않아 반복 실패를 줄입니다.
- 인작/스선 수는 조회 가능한 작품 목록을 최대 2,500개까지 순회해서 계산합니다. 조회가 불완전하면 댓글을 남기지 않습니다.

**중요:** 개발자도구 콘솔 방식이므로 페이지를 새로고침하거나 탭·브라우저를 닫으면 봇이 중단됩니다. 24시간 상시 운영되는 서버 봇은 아닙니다. 기존 확장 프로그램 구현은 Git 커밋 이력에 남아 있으며, 이 저장소의 현재 버전은 콘솔 방식입니다.

## HTTP 400 사용자 검색 오류 및 비공개 data.json 사용

로그인한 엔트리 계정에서도 닉네임 검색 GraphQL API가 HTTP 400을 반환하는 경우를 확인했습니다. 또한 `ent2-backup`은 **비공개 GitHub 저장소**여서 공개 RAW 링크를 직접 가져오는 방식은 HTTP 404로 실패합니다.

**비공개 닉네임 데이터베이스를 공개하지 않고 사용할 수 있는 방법:**

1. GitHub에 로그인해 본인의 비공개 `https://github.com/entrykinetictypo/ent2-backup/blob/main/data.json`로 이동합니다.
2. `Download raw file`(원본 다운로드)로 **data.json**을 내 PC에 다운로드합니다.
3. 엔트리 이야기 탭에서 최신 `console.js` 코드를 실행합니다.
4. 콘솔에 `EntryInfoBot.loadDatabase()` 입력 후 엔트리 페이지 **오른쪽 위의 초록색 파일 선택 버튼**을 클릭합니다.
5. 내려받은 `data.json`을 선택합니다. 콘솔에 `ent2-backup 개인 DB 준비 완료`가 뜨면 완료입니다.
6. `await EntryInfoBot.test("삼류")`로 API 조회를 먼저 확인합니다(댓글은 달지 않음).
7. 조회가 정상이면 `await EntryInfoBot.replyToOwnPost("삼류")`로 예전에 올린 내 명령어 글 **모두를 예약**할 수 있습니다. 다른 사람의 글까지 포함하려면 `await EntryInfoBot.replyToAllRecentCommands()`를 실행합니다.

파일을 로드하는 대신 API가 정상 작동하는 사용자는 그대로 이용할 수 있습니다. 닉네임 존재 여부를 정확히 알 수 없을 때는 답글로 `그런 유저 없음`을 쓰지 않습니다.

실제 엔트리 사이트에서 추가 문제가 있을 수 있으므로 API 오류가 나오면 결과를 확인해야 합니다.

## 개발 및 테스트

Node.js v22 이상에서:

```sh
node --check console.js
node --test tests/*.test.js
```

GitHub Actions에서도 커밋마다 문법 검사와 모의 GraphQL 응답 테스트를 실행합니다.

이 도구는 엔트리 공식 서비스가 아닙니다. 엔트리의 운영 정책과 자동 댓글 허용 여부를 확인한 뒤 사용하세요.
